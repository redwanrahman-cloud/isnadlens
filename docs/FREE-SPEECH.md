# Natural read-aloud for the competition

Google's current [Gemini speech guide](https://ai.google.dev/gemini-api/docs/speech-generation) provides a verbatim transcript API and WAV audio for Gemini 3.8 Flash TTS. The language table includes our nine languages. [Pricing](https://ai.google.dev/gemini-api/docs/pricing) lists free-tier input and output. This does not establish any particular account's availability: [active project rate limits](https://ai.google.dev/gemini-api/docs/rate-limits) must be checked in AI Studio. Free-tier text can be used to improve Google's products; the reader discloses this before generation.

Use a project with no paid billing linked. A locally entered key and explicit free-tier confirmation are required; the app cannot independently inspect Google's billing state. Do not activate a billed project merely because an app limit exists. Local configuration lives in ignored `artifacts/private/google-speech.env` or environment variables; keys never go to the browser. No subscription, paid fallback or automatic provider retry is implemented.

The app limits new requests to two per minute and sixty per UTC day in a persistent local quota ledger. Failed requests count. Google's quota may be lower and shared with other apps. Identical text/language/voice/model requests reuse cached audio. The three voice choices are Achernar, Algieba and Sulafat. Text is bounded to 2,400 characters per request; longer text can use the device reader. Private-data patterns are rejected before transmission. The service is intended for displayed public explanations and source passages, not private user documents.

Audio uses native browser controls and starts through a user action, avoiding mobile autoplay assumptions. It needs no installed Microsoft voice. [Apple's media guide](https://developer.apple.com/library/archive/documentation/AudioVideo/Conceptual/Using_HTML5_Audio_Video/AudioandVideoTagBasics/AudioandVideoTagBasics.html) documents WAV playback in Safari on iOS. Actual iPhone/Android playback and pronunciation quality still require device testing. The existing device reader uses [voices exposed by the current browser/device](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis/getVoices), which may be Apple, Google, Microsoft or another provider.

Live local connection verified on 4 October 2026 after Redwan confirmed no paid billing linked. English Algieba and Arabic Sulafat returned HTTP 200 with validated WAV audio (343,986 and 374,706 bytes). Repeating the English request returned a cache hit with identical bytes and no new generation. These are technical generation checks, not independent pronunciation/tajwid review. Keys and audio cache remain excluded from Git and production traces.

Synthesized reading is not an admitted Quran recitation or scholarly authentication. Generated pronunciation and transcript fidelity require listening checks; intact displayed quotations remain the source of record. Missing keys, quota exhaustion, provider errors and malformed audio produce an unavailable state with a selectable device-reader fallback.

The local cache/quota ledger is not a shared multi-instance hosting control. Durable shared controls, cache expiry/storage limits and protection against public endpoint abuse remain deployment gates.
