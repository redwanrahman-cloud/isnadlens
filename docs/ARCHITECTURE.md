# Event-window architecture

Created after Redwan authorized the build on 4 October 2026.

Claim intake → deterministic scope/privacy boundary → frozen admitted-corpus lexical retrieval → exact source/locator/quotation/hash checks → authorized structured semantic assessment → rule-constrained corpus-bounded verdict → sealed record → presentation.

Source quotations remain immutable. Quran search uses the separate official Arabic Simple Clean edition. Hadith search uses official HadeethEnc record fields with each publisher language, version, grade, reference and explanation preserved. Corpus selection is explicit; publisher grades are attributed and never independently assigned. User-query variants do not rewrite stored source strings. Source admission, citation integrity, AI semantic judgment and human review are separate objects.

Fresh verification requires a configured API key and paid-call authorization. Real assessment was tested after funding on 4 October 2026. Persistent spend reservations enforce the approved local development cap, including conservative reservations when request usage is unknown. The offline interface may show retrieved authentic passages, but does not claim semantic verification. Synthetic tests are not public religious evidence. No pilgrimage corpus has been admitted.

The first increment implements Arabic and English interface views. Four additional output languages, renderer semantic invariants, deployment, independent semantic evaluation, release packaging and optional pilgrimage utilities remain later acceptance gates. None is advertised as complete.

The HTTP route bounds request bytes, caps concurrent work and applies a single-process request limit. A trusted-edge durable limiter and persistent authorized spend budget are required before public operation. No personal claims are written to logs or disk.
