# Free offline testing before paid validation

Run `npm run test:offline` from the implementation directory. For a smaller twelve-question retrieval sample, run `node scripts/offline-boundary-lab.mjs`. These commands require the existing local admitted sources and private saved API records. They never load `.env.local`, explicitly disable paid/speech authorization, remove provider keys from their own process, reject network fetches, and verify that the spending ledger is unchanged. Missing or invalid captures stop the run; there is no live fallback. The controls affect this command, not the running application.

The lab has three layers:

1. Exact historical replay of the 100 captured question records. The key includes the full original question, language, source selection, corpus identity, supplied evidence/context, routing/search metadata, model and prompt/schema/router versions. A changed question, packet or version raises `REPLAY_CACHE_MISS_REQUIRES_LIVE`. Replayed costs are historical; new replay cost is zero. The replay is a separate script utility, never an application provider or user-facing answer mode.
2. Injected failure patterns around those real responses: missing/duplicate assertions, invented citations/quotations, wrong context, lost attribution/qualifications, uncertain decisions, invalid integrity and seal tampering. These run the actual deterministic app guards. A deliberately well-formed positive review is an injected control, not a religious judgment.
3. Local source retrieval with original questions, polite prefixes and Unicode forms. Fixed historical search hints are reused; no new multilingual AI detection, translation or planning is performed. The full run covers 94 source-answer-eligible questions. References are consulted only after retrieval, and exact primary cards and immediate supplied Quran context are distinguished. Repeated Unicode forms may have identical text; probe counts are not independent new questions.

The JSON report gives group counts, policy-only differences, source-search probes and a source-triage queue. Review alternative evidence before scheduling a paid run: failing to retrieve every reference witness does not necessarily mean the app answered incorrectly. Prioritize genuine source gaps, changed prompts/models, attribution/negation/exception boundaries and fresh language input. Keep the paid result and its independent source audit separate from the offline report.

This does **not** reproduce an LLM's weights or predict its answers to new questions. The known wrong-source strength/anger response demonstrates why: an injected incorrect semantic yes with genuine unrelated evidence can pass pure citation mechanics. A real source-focused model and independent reference review are still required to assess meaning. Never label thousands of injected guard checks as thousands of successful Islamic answers or use a reference-answer lookup as production reasoning.
